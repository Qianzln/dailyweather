## 2. 修的 5 个真 bug

### 2.1 AGSL `HIGHLIGHT` 漏声明 uniform → 雨类天气必崩（P0）

`RainRefractionShader.HIGHLIGHT` 的 `COMMON.DropLayer()` 里用了 `uRunningDropSize`，
但 uniform 声明块漏了它。AGSL 在**运行时**才编译，`RuntimeShader(source)` 直接抛
`IllegalArgumentException: error: 31: unknown identifier 'uRunningDropSize'` —— 这不是异常分支，是**必崩**。

**修**：
- 补 `uniform float uRunningDropSize;`；
- `newShader()` 用 `runCatching` 包住，编译失败**返回 null 降级**（只是没有雨滴效果，远好于崩溃）；
- 调用点去掉 `!!`（否则降级后变 NPE）；
- `GlassRaindropsCard` 补 `Arrangement` / `FontWeight` 两个 import（此前编译不过）。

### 2.2 校准 harness 的两处坑（不是 App bug，但会让校准结果全错）

| 现象 | 真因 | 修 |
|---|---|---|
| 8 个场景全部落到同一个键 | `pm uninstall` 后**没有城市** → App 停在定位权限弹窗 → 从不走 `refresh(city)` → fixture 永不注入 | 截图前 `pm grant` FINE/COARSE_LOCATION + POST_NOTIFICATIONS |
| 个别场景沿用了上一场景的数据 | Activity 是 **singleTask**，旧进程还活着时 `am start` 只把旧实例提到前台，`onCreate` 不跑 → `--es fixture` 被忽略 | `am start -S` |
| `cloudy_day` 总错成 `partly_day` 的 58 | fixture 快照会被 **`weatherStore.putSnapshot()` 持久化**，下一场景冷启动先读残影快照且可能「够新不刷新」 | 每场景 `pm clear`（再重新授权） |

### 2.3 玻璃雨滴卡整卡空白（视觉 bug）

**症状**：雨天/雷天首屏有一块 **176dp 全空白卡**——水珠、文字都没有，只剩玻璃底色。

**根因是三层叠加，缺一不可**：

1. 卡片由 `AnimatedVisibility + expandVertically` 展开，**首帧高度是 0**；
2. `Modifier.graphicsLayer { size }` 的 block 只在**布局尺寸**这个上游事件上重跑，
   实测只跑了那一帧，`size = 0×0` 被写进 `uSize`，此后再不刷新；
3. 旧 `SDF` 里 `gradRadius = min(radius*1.5, min(halfSize)) = min(…, 0) = 0`
   → `normalize(0)` = **NaN** → `refractedCoord` = NaN → `content.eval(NaN)` → **整层透明**。

**修**：
- `SDF` 加防 NaN 兜底：`uSize ≤ 1` 或 `uRefractionHeight ≤ 0.5` 时直接 passthrough；
  `circleMap` 内部 `clamp`（否则 `sqrt(负数)` = NaN，这个 NaN 会顺着 `d` 传染整层）；
  `gradRadius` 设 0.5 下限；`refractedCoord` clamp 到 `[0, uSize]`。
- uniforms 改由 **`onSizeChanged`** 驱动，不再在 `graphicsLayer` block 里读 `size`。
  实测修正后日志：`SDF uniforms: size=996.0x462.0`（正确）。

### 2.4 水珠密度被放大 5 倍（视觉校准）

`uStaticDropSize / uRunningDropSize = 1f` 是南风按 **1080×2400 全屏**标定的
（`Drops` 里 `uv *= 40.0 / size` ⇒ 每 60px 一颗静止水珠）。
AGSL 的 `uv = (xy - 0.5·res) / res.y` 让网格数量**只随层高变化**，
把同一套参数搬到 462px 高的玻璃卡上，密度就放大 5 倍 → 实测像**噪点雪花**，不是雨滴。

**修**：`dropScaleFor(height) = max(1, 2400 / height)`
—— 全屏（height=2400）恰好退回 **1.0**，与原版参数完全一致（天空层折射不走样）；
卡片（height=462）得 5.2。另把水珠 alpha 由 0.85 降到 0.55（0.85 时是一坨坨白斑）、
`SdfRefractionAmount` 12dp → 9dp（原先左下角标题被横向拉伸得偏重）。

### 2.5 `Fixture.hourOverride` 对场景键无效 → 白天场景永远验不到

`SceneBridge.phaseOf` 用了 `hourOverride`，但 `oppoSceneKeyOf` 直接用 `nowEpochMs` 算 `LocalTime`。
模拟器时区 UTC，18:xx → 槽位 6（夜）→ 8 个 fixture 全落夜档。
**修**：`oppoSceneKeyOf` 里也走 `hourOverride`（release 下该值恒 null）。

### 2.6 `cloudrateProxyOf` 的死代码

`when` 里 `contains("CLOUDY")` 排在 `startsWith("PARTLY_CLOUDY")` **之前**，
`PARTLY_CLOUDY_DAY` 先命中前者 → 后者永不生效 → 「少云 58」永远轮不到，
`partly_day` 与 `cloudy_day` 会选到同一个键。
**修**：调换顺序；partly 的代理云量 0.40 → 0.20（必须 < `CLOUD_LOW = 0.30` 才会选 58）。

## 4. 复现方式

```bash
export MSYS_NO_PATHCONV=1
export ADB=D:/DEV/android-sdk/platform-tools/adb.exe
bash tools/shoot_fixtures.sh C:/Users/qiankun/AppData/Local/Temp/dw_fixtures
```

脚本每场景会打印 `<fixture> -> <截图字节>  <场景键>  [**崩溃**] [**未注入**]`
—— 后两个标记为空才说明这次校准有效。

单场景手动跑：

```bash
adb shell pm clear com.dailyweather.app
adb shell pm grant com.dailyweather.app android.permission.ACCESS_FINE_LOCATION
adb shell pm grant com.dailyweather.app android.permission.ACCESS_COARSE_LOCATION
adb shell am start -S -n com.dailyweather.app/.MainActivity --es fixture rain_day
```

## 5. 遗留（真机才能做）

1. **GL 粒子**：`#version 320 es` compute + SSBO 需 **GLES 3.2 真机**。
   模拟器日志：`OppoParticles: 跳过粒子：需要 GLES 3.2（当前 3.1）`。
   本批已确认**整层降级不崩**，但雨/雪/沙尘/星/流星的粒子观感**尚未验证**。
2. `meteor` 的 orbit/flare 动画未做（南风 `g.java:880` 把它特判成 `meteors` 列表）。
3. `OppoSceneRenderer` 里 `glGetUniformLocation` 逐帧调用未缓存（性能）。
4. 雾/沙尘场景在无 GLES 3.2 时**没有任何粒子层**，画面偏空——真机验证后再评估是否需要 CPU 兜底。
