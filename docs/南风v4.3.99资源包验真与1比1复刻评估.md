## 4. 「1:1 复刻」的两个层级

### L1 · 视觉同源（推荐先做）

用 `pack.json` 的 62 预设**原数据** + 44 张 OPPO 原版贴图，驱动**现有 Compose/AGSL 渲染器**。

| 项 | 来源 | 落地 |
|---|---|---|
| 天空 5 段渐变 | `_Color0..4` + `_Segment1..3` | 替换 `SpriteSky` 的渐变 stops |
| 云：数量/组别/alpha/位置 | 实体名 `cloud_{组}{号}_{槽}_{alpha}_{x}_{y}` | 生成 `ScenePreset` 注册表 |
| 云光照 | 9 张 `*_normal.png` | normal map 光照（Compose 侧近似或 AGSL） |
| 太阳 + 6 层 halo | `sun_main_*` / `sun_halo1..6_*` | 太阳绘制层 |
| 雷 5 帧 | `thunder_0..4` + `flash` | 替换现程序化闪电 |
| 雨/雪粒子 | `particle_rain(_front)` / `snow-p` | 粒子密度取自场景 |
| 光照方向 | `DirectionalLight_1..3` | 云的明暗/朝向 |
| 噪点 | `noise.png` / `u_NoiseScale`/`Strength` | `NoiseHaze` 参数 |

- **可达性：高**。不需要换渲染器，纯数据驱动 + 素材替换。
- **成本：中**。主要工作是写 `pack.json → Kotlin ScenePreset` 的转换器 + 改渲染器读预设。
- **收益：观感差异的绝大部分**（配色、云型、层次、密度、闪电都是原数据）。

### L2 · 同架构（GLES 全移植）

新增 EGL/`GLSurfaceView` + VAO/VBO + SSBO compute 粒子双缓冲 + normal map 光照 + 32 个 GLSL。

- **成本：极大**。等于从零写一个渲染器 + 场景图运行时 + 着色器加载管线。
- **收益：有限**。主要体现为粒子数量上限与真实光照；观感差异在 L1 已吃掉大半。
- **风险（关键）**：`#version 320 es` = **GLES 3.2**。`minSdk 26` 设备未必支持；
  **当前模拟器（swiftshader）大概率不支持 compute**，意味着 **L2 在现有环境里根本没法验证**——只能盲写。

## 5. 建议路线

```
第一步  L1-A  导入 44 张 OPPO 贴图（已验真，可直接拷贝）
        L1-B  写 pack.json → ScenePreset 转换器，生成 62 预设的 Kotlin 注册表
        L1-C  渲染器改为读预设：天空 5 段渐变 / 云组与 alpha / 太阳 halo 栈 / 雷 5 帧
        ── 出样张对比，确认观感 ──
第二步  评估 L2 是否值得（先解决 GLES 3.2 验证环境，否则不启动）
```

**为什么先 L1**：
1. 无论走不走 L2，预设系统与素材都是**前置**——先做不会浪费；
2. L1 就能拿到绝大部分观感收益，且**可以在现有模拟器上验证**；
3. L2 无法在当前环境验证，盲写一个渲染器风险过高。

**关键实现决策（都已写进代码注释，避免后人改错）**

| 决策 | 理由 |
|---|---|
| 用 **TextureView** 而不是 `GLSurfaceView` | Haze 靠"把源 composable 渲染进离屏图层再模糊"工作；`SurfaceView`/`GLSurfaceView` 走独立 Surface + SurfaceFlinger 合成，**内容不在宿主 View 的 display list 里，Haze 采样不到**（顶栏会一片黑）。`TextureView` 的内容作为硬件层画进父 View 画布，可被捕获 |
| 四边形取 **2×2**（顶点 ±1），不是 ±0.5 | background 的 `scale.y = 2.2222` 恰等于 baseline 2400/1080；2×2 半高 1 乘上它纵跨 ±2.2222，正好等于 ortho 半高 → 铺满全屏。用 ±0.5 会让所有云/太阳缩一半并偏到下半屏 |
| 上传贴图**前**做一次行序翻转 | 源 PNG 文件保持不翻转（遵守 README）；但 Android Bitmap 第 0 行是图像顶部，而 `glTexImage2D` 把首行当 `t=0`，本项目 UV 取标准约定（`t=0` 在下，依据天空着色器把 `uv.y=1` 映射到天空顶部）→ 两者差一次翻转，在**上传时**补 |
| `range <= 0` 时兜底为 200 | 云着色器算 `range = light.range / 200.`，原数据里个别预设 `range = 0` → 除零 → attenuation NaN → 整层云变黑 |

```
                   └─→ effects[1].uniforms → 扰动 compute
                                        ↓
                  SSBO 当顶点缓冲 → glDrawArrays(GL_POINTS) → 实体 frag 采样精灵
```

粒子结构 **96 字节 = 6×vec4**：

| 偏移 | 字段 | 含义 |
|---|---|---|
| 0 | `position` | xyz = 位置（**裁剪空间**），w = 大小 → `gl_PointSize` |
| 16 | `acceleration` | x = 随机角，z = 景深扰动系数 |
| 32 | `speed` | xyz = 速度，w = 随机种子 |
| 48 | `color` | rgba |
| 64 | `lifeTime` | x = 当前生命，y = 总生命，w = alpha 随机 |
| 80 | `originPos` | 仅 compute 用，不参与顶点属性 |

顶点着色器**显式声明 `layout(location = 0..4) in vec4`**，只用前 5 个 vec4、跨度仍 96 字节
→ `glVertexAttribPointer(loc, 4, FLOAT, false, 96, loc*16)`。
因此 `OppoShaderLibrary` 现在**优先识别显式 location**，只有没写的（场景图那批）才退回
`a_position→0 / a_texCoord→1` 约定；不区分的话粒子的位置数据会喂给 `acceleration`。

**粒子位置已在裁剪空间**：`gl_Position = vec4(position.xyz, 1.0)`，不乘矩阵。
雨的 `emitterPosition = [-0.25, 1.2]` + `emitterSize = [1.2, 0.2]` → 出生 y ∈ [1.0, 1.4]，
即**在上边缘之外**，再以 `direc = [0.25, -1, 0]` 落进视野——这是雨的设计，不是越界。

### 7.8 首次装机验证结论（v0.1.40）

**首次真正运行**（此前各批次只验过编译）。修的 5 个真 bug + 一处**归因更正**详见
`release/notes-v0.1.40.md`，要点：

1. **`glReady` 永久卡 false** —— `remember(currentCity?.id)` 在"定位完成"时把 state 重建为 false，
   而 GL 层不会重新回调 → 顶栏一直叠着异常 Haze。改 `remember {}`（GL 就绪是进程级事实）。
2. **时区混用** —— `sunrise/sunset`（数据源当地时刻）与 `now`（缺时区时回退设备时区）不同源。
   修：`City.inferZoneId()` 按经度兜底。**实测场景键由 `1_3_sunny-afternoon` 纠正为 `17_6_fog-night`**。
3. **顶栏「深浅跳变」** = 自创的 `alpha = 0.08 + 0.84*strength`（南风源码**没设 alpha**）→ 删。
4. **顶栏「边缘方形」** = `backgroundColor = 主题中间色`（不透明底色把顶栏填成实色矩形）→ 删。
   量化：边界处 Δ 由 **112** 降到 **29**（肉眼不可辨）。
5. **卡片底部浅色圆弧** = `GlassCard` 里自研的斜向白光 → 移除。
6. **卡片色调与天空割裂** = `glassTint` 只有昼/夜两档硬编码，清晨/黄昏被误判成昼 → 改为跟随天空中部色。

**归因更正（重要）**：v0.1.36 那条"亮带"我原先归因于「**Haze 采不到 TextureView**」，
**真因是 tint 用了浅天蓝 `#A5C9E6` 叠在深色天空上**。平滑渐变天空「模糊后 ≈ 原样」，
所以"没生效"与"生效但看不出"在静态截图上是同一种样子 → 我据此下了过强结论。
tint 修正后**顶栏已恢复南风 Haze 配置**。实测顶栏上半部能完全遮住穿过的 Hero 温度数字
（说明有实底，不只是 32% 半透明 tint），下半部按 `progressive` 渐隐 —— 南风同款行为。

**其它**：44/44 贴图上传成功、22 组/62 键与 64 预设/583 实体加载 131 ms、卡片顺序与间距符合南风；
AQI 有数据时正常，紫外线/能见度空是**数据源不提供**（诚实降级）。

### 7.5 粒子系统：数据齐全，只缺 GPU 管线

早期判断「粒子参数在未导出的 materials 表里」**是错的**——整段就在 `pack.json` 的实体里，
是转换器把它丢了（只留了 `role`）。现已完整搬运，共 **41 个粒子实体**，角色：
`rain` / `rainfront` / `snow` / `dust` / `star` / `meteor`。

每个粒子实体带：

```
compute    particle/<guid>.cs                          ← 主发射 compute（#version 320 es + SSBO 双缓冲）
uniforms   activeParticeNumber / emitterPosition / emitterSize / depthRatio /
           direcMin|Max / minColor|maxColor / alphaRange / speed / lifeTime /
           sizeAndNoise / rotationAxis / emitterInfo /
           三档景深 closeSpeed|closeSize|closeAlpha|closeDisturb（+ mid / far）
effects[]  追加 compute 通道（windDirec / windForce / turbulenceIntensity / turbulenceFrequency）
```

⚠️ **粒子精灵贴图是替代映射**：原引用写成 `material/<uuid>/<role>`，指向未导出的表；
转换器按角色名兜底到 `textures/particle/{rain-p,snow-p,star3}.png`。

> 更正（v0.1.36 复查）：`meteor` **不是"无素材"** —— 它的贴图就是
> `{'rain': 'textures/particle/rain-p.png'}`，**复用雨的拖尾贴图**，包内没有独立 meteor 素材是正常的。
> （`texture_fallback_pack.zip` 里那 3 张 PNG 与项目已有的 **MD5 完全一致**，无新素材。）
> 另：`g.java:880` 把 meteor **特判**成 `meteors` 列表走 orbit/flare 动画，不走通用 `particleDraws` ——
> 本项目目前按通用粒子路径渲染它，缺那层 orbit/flare。

### 7.6 已知风险

1. **APK 体积**：release 从 6.9 MB → **16.6 MB**（assets +11 MB，与预测一致；南风 v4.3.99 自己 23 MB）。
   要压可把 44 张 PNG 转 WebP（云贴图带 alpha，需验证不损 normal map 精度）。
2. **GLES 3.2 兼容**：compute 需 3.2；模拟器（swiftshader）大概率不支持 → 粒子只能真机验。
   渲染整层设计为可降级（能力不足或着色器编译失败即整层跳过，回退 Compose 渲染器）。
3. **`hazeSource` 捕 `TextureView`** 是架构上最不确定的一点：若捕不到，毛玻璃失效（不崩，天空仍可见）。

### 7.9 8 场景视觉校准结论（v0.1.41 · debug 包）

完整报告见 **`v0.1.41-8场景视觉校准报告.md`**，定稿截图在 `calibration/v0.1.41/`（8 PNG + 8 log）。

**8 个场景键全部命中**（无崩溃）：

| fixture | skycon | 场景键 |
|---|---|---|
| clear_day | CLEAR_DAY | `1_3_sunny-afternoon` |
| clear_night | CLEAR_NIGHT | `1_6_sunny-night` |
| partly_day | PARTLY_CLOUDY_DAY | `58_3_cloudy-afternoon`（少云 58） |
| cloudy_day | CLOUDY | `56_3_cloudy-afternoon`（多云 56） |
| rain_day | LIGHT_RAIN | `6_2_L-rain-noon` |
| thunder_day | THUNDER_SHOWER | `21_2_thunder-noon` |
| snow_day | MODERATE_SNOW | `10_2_L-snow-noon` |
| fog_day | FOG | `17_2_fog-noon` |

**修的 5 个真 bug**（详见报告 §2）：

1. **P0**：`HIGHLIGHT` 漏声明 `uRunningDropSize` → 雨/雪/雷进首页**必闪退**
   （AGSL 运行时编译抛 `IllegalArgumentException`）。补声明 + `newShader` 降级 + 去 `!!`。
2. **玻璃雨滴卡整卡空白**：三层叠加 —— `expandVertically` 首帧高 0 → `graphicsLayer{size}` 只跑一帧
   → `uSize=0×0` → 旧 SDF 的 `normalize(0)`=NaN 传染整层。修：SDF 防 NaN 兜底 +
   uniforms 改由 `onSizeChanged` 驱动。
3. **水珠密度放大 5 倍**：原参数按 2400px 全屏标定，卡片只有 462px。
   修：`dropScaleFor(height) = max(1, 2400/height)`（全屏退回 1.0，天空层不走样）。
4. **`Fixture.hourOverride` 对场景键无效** → 白天场景永远验不到（全落夜档）。
5. **`cloudrateProxyOf` 死代码**：`contains("CLOUDY")` 抢在 `startsWith("PARTLY_CLOUDY")` 前，
   「少云 58」永远轮不到，`partly_day` 与 `cloudy_day` 会同键。

**harness 三坑**（会让校准结果整体失真）：`pm grant`（否则无城市→不刷新）、
`am start -S`（singleTask 复用旧实例→intent extra 被忽略）、
每场景 `pm clear`（fixture 快照会持久化→下一场景截到残影）。

**遗留**：GL 粒子需 GLES 3.2 真机（模拟器 3.1，日志 `OppoParticles: 跳过粒子`）；
`meteor` 的 orbit/flare 未做。
